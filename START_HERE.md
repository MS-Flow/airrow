# START HERE

Welcome to Arrow. This is your guided first hour, whether you're a human engineer or an AI assistant.

## 1. Understand the product (15 min)

1. `docs/VISION.md` — what Arrow is, for whom, and why now
2. `docs/PRODUCT_CONSTITUTION.md` — the ten principles every feature is judged against
3. `context/PROJECT.md` — the condensed business context

Key mental model: Arrow is where founders **prepare to build**, not where they build. The generated repository is the product.

## 2. Understand how we work (15 min)

1. `docs/ENGINEERING_CONSTITUTION.md` — the rules of engineering here
2. `specs/README.md` — the spec system: no spec, no code
3. `checklists/FEATURE_CHECKLIST.md` — the per-feature workflow you will actually follow
4. `context/CONSTRAINTS.md` — hard rules, never broken

## 3. Understand the system (20 min)

1. `docs/architecture/SYSTEM_ARCHITECTURE.md` — monorepo, headless engine, jobs, delivery
2. `docs/architecture/DATABASE_DESIGN.md` — the data chain: org → project → interview → model → job → artifact → delivery
3. `docs/architecture/UI_ARCHITECTURE.md` and `INFORMATION_ARCHITECTURE.md`
4. `adr/` — why the big decisions went the way they did

## 4. Find your work (10 min)

1. `context/PROGRESS.md` — current state and next actions
2. `roadmap/MILESTONES.md` — where we are in the plan
3. `roadmap/BACKLOG.md` — the prioritized queue; take the top unfinished item

Then: follow the feature checklist. Spec first. Always.

## For AI assistants

`CLAUDE.md` is your entry point and contains the reading order and rules. `prompts/PROMPT_LIBRARY.md` contains proven prompts for each workflow stage — humans, use them; AI, expect to receive them.
