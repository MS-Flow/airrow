# Airrow — Spec Constitution

The non-negotiables every spec and every change must respect. This is the single governance file the
spec-workflow commands read. It **links to** the canonical sources rather than copying them, so it
can't drift.

## I. Architecture invariants
- **One-way data flow.** `app/**` routes (RSC by default) → client components → Server Actions /
  Route Handlers → feature `queries.ts` / `actions.ts` → the DataStore
  (`apps/web/src/lib/data/store.ts`). Never reach around a layer.
- **External calls are server-side only, in one place each.** Claude API only via the generation
  engine's authoring provider; Supabase / GitHub App only via the DataStore and server actions.
  Never from client components; never from `packages/engine` or `packages/schemas`.
- **The engine stays pure.** `packages/engine` is a headless `generate(projectModel) → RepoTree +
  Manifest`. `packages/engine` and `packages/schemas` **never** import from `apps/*` and **never**
  read `process.env`.
- **Return types & errors.** `any` is forbidden (TypeScript strict). The engine returns typed error
  results, not thrown strings; the app surfaces errors via Sentry. Every boundary is Zod-validated —
  forms, actions, engine I/O, **and all LLM output** (validated against document contracts before
  acceptance; retry with feedback on validation failure).
- **Autogenerated, never hand-edited:** `pnpm-lock.yaml`, `.next/`, generated repo artifacts under
  `.data/`, and Supabase-generated types.

## II. Data invariants
- **Tenancy by `organization_id`.** Every resource hangs off an organization; each user gets a
  personal org at signup.
- **RLS everywhere.** Every table has Row-Level Security **with denial tests** — no exceptions,
  including "internal" tables. Access control is added on every new table/resource in the same change.
- **Migrations are code.** Idempotent, replay cleanly from zero, and committed to the repo. Never
  hand-edit the schema in the Supabase dashboard.
- **Manifest of record.** Generated output records per file (source, template id + version, prompt
  version, model, inputs hash) in Postgres — do not bypass it.
- **Repo access via GitHub App installations only** — never user PATs.

## III. Design invariants
- **Tokens, not literals.** Use the Tailwind v4 / design-system tokens (colors, spacing, radii,
  typography) — never hardcode hex/px values in components.
- **Reuse before create.** Reuse the shared shadcn/ui-based components (`apps/web/src/components/ui`)
  before writing a new one; extend the system rather than forking it.
- **Sanitized rendering.** Generated/authored Markdown is untrusted — render sanitized (DOMPurify),
  never execute it.

## IV. Process invariants  (PORTABLE — keep as-is, only names change)
- We work via GitHub: a **feature** is a GitHub Project, and **issues** are linked to that feature.
  Each issue gets a spec and a branch.
- **Spec before code.** Every issue gets a `specs/NNN-kort.md` before implementation.
- Branch `NNN-kort` (issue number + short name, **no** `issue/` prefix) is cut from its `feature/<name>`.
- **PR direction is strict and never skipped:** issue branch → its `feature/<name>` → `develop` →
  `main`. An issue branch is **never** PR'd to `main` or `develop`. If unsure which feature an issue
  branched from, check `git merge-base` or ask.
- After implementing: check off acceptance criteria, set the spec **Status**, and update
  [`specs/README.md`](../../specs/README.md).

## V. Testing invariants  (PORTABLE — test runner is Vitest)
- Tests are **co-located** with the code they cover (`*.test.ts` / `*.test.tsx`), matching Vitest's
  glob so they run in CI automatically.
- Tests must be **deterministic**: no dependence on local time/timezone, randomness, or the network.
  Pin `TZ=UTC` and anchor fake time in UTC (`vi.setSystemTime`).
- Each spec's **Verification** section names the tests it adds.
- `/implement` writes the tests; `/analyze` confirms they exist and are green before closing a spec.

## VI. Verification bar  (Airrow stack commands)
A change is not done until:
- Typecheck is clean:  `pnpm -r typecheck`
- Linter adds **no new** issues:  `pnpm -r lint`
- Tests are green:  `pnpm -r test`  (single file while iterating: `pnpm --filter web test <file>`) —
  noting known pre-existing failures.
- The relevant acceptance criteria are demonstrably met (by a test or an explicit manual check).

> Tooling note: `pnpm -r lint` (ESLint) and `pnpm -r test` (Vitest) are the agreed commands. If a
> package does not yet have its `lint` / `test` script and dev-dependency wired, add it as part of
> the first change that needs it — do not silently skip the bar.
